# DiPlay v0.3.9 — Surface建立时激活过渡缩小防护、RTSP请求在飞时推迟释放蓝牙引导

## 更新

- **Surface 首次建立时激活过渡缩小防护基线，消除启动黑边锁定**（Issue #363）：
  - 修复 #290 的过渡缩小（transitional-shrink）防护仅在高度增长触发 Surface 重新挂载时激活基线的问题；
  - 针对 Activity 恢复直接以全屏建立 Surface 的场景，补充在初次确立尺寸时即记录基准尺寸与 3 秒稳定窗口；
  - 过滤启动约 0.75 秒后到达的过渡缩小调整，防止小尺寸被重新锁定导致会话全程出现黑边，同时保留 3 秒窗口后真实倒车等尺寸缩小的正常生效。
- **RTSP 请求处理期间推迟释放 USB 蓝牙引导通道，提升无线握手成功率**（Issue #316）：
  - 修复在检测到传输后配置与 AirPlay TCP 后固定 1 秒直接关闭 USB 蓝牙引导传输通道的问题；
  - 当遇到耗时较长的 RTSP 配对握手（如 pair-setup 阶段耗时数秒）时，固定延时释放会直接从底层切断传输通道，造成 RTSP 超时断连；
  - 现改为在存在未完成 RTSP 请求（`inFlight > 0`）时循环推迟释放，等待请求应答完毕后再平滑释放，大幅提升无线配对握手的稳定性和容错能力。
